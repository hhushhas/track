## Two specs written

**`docs/COMPANY_RELATIONSHIPS_SPEC.md` (`18aea90`)** — first-class Companies,
inter-company relationships, and shared channels. Key decisions: a relationship is
**one multi-company peer network**, not bilateral edges; relationship membership
alone grants no project or content access; a company joins a shared project only
when its owner/admin accepts an invitation; administrative roles **never** bypass
explicit channel membership. Relationship-relative roles (`staff`, `client`) were
replaced with neutral company roles (`owner`, `admin`, `member`) and project roles
(`manager`, `member`). Exiting companies retain a read-only point-in-time archive.
Shared project archival requires approval from every active participating company.
Company discovery stays private — exact handle, verified invitation, or secure
link; no browsable directory. Architecture review added multi-company identity
isolation (reads never union across a user's represented companies), immutable
project origin, tombstoned attribution, and a two-phase immutable project-memory
exit snapshot.

**`docs/TASK_MANAGEMENT_SPEC.md` (`a4cd40a`)** — first-class tasks. Hasan chose a
human-reviewed task draft inbox, multiple boards, source-group visibility
inheritance with authorized promotion, project-wide or single-group board scope,
tasks plus subtasks, live task cards attached to source chat messages, and
automatic high-confidence detection on by default with a per-group owner/admin
control. Pre-acceptance AI output is called a **task suggestion** to avoid
colliding with the removed Draft Records concepts. Independent critique closed
authorization and lifecycle blockers: scope-locked acceptance, opaque task keys,
generation/lease/cursor compare-and-set detection, invalidatable evidence
snapshots, an explicit suggestion state machine, and atomic default provisioning.

The two specs were written concurrently in a shared worktree and explicitly
reconciled against each other, with Phase 7 retained as the combined-release
dependency.

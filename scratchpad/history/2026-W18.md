## Store submission lane (04-27 → 04-28)
A long chain of external blockers, each resolved:
- Android EAS build failed on Gradle resolving
  `org.asyncstorage.shared_storage:storage-android:1.0.0` → removed the unused
  `@react-native-async-storage/async-storage` rather than carrying the native dep.
- Expo queue was the real bottleneck (Android position 1903, ~8695s).
- Play submission rejected for a missing privacy policy URL → added a public
  `/privacy` route and registered `https://track.q9labs.ai/privacy`.
- Hosted Google sign-in 500 on `/api/auth/sign-in/social` traced to Convex auth;
  fixed by setting `BETTER_AUTH_SECRET` on production Convex.
- iOS build failed importing the distribution certificate → re-exported the P12 in
  a keychain-friendly format via ignored `apps/mobile/credentials.json`; Apple Team
  `5K9635LZ6F (CollabEZ FZE LLC)`.
- EAS submit kept reporting missing Play metadata, so the Android internal lane
  was completed manually in Play Console (AAB build 4 / 1.0.0).

**Result:** iOS build 4 processed as version 1.0.0, added to TestFlight
`Internal Testers` (`READY_FOR_BETA_TESTING`), full App Store metadata completed,
App Privacy published as `Data Not Collected`, and review submission
`86c9bfc4-8e67-4886-933f-8287ddcc176b` created — `WAITING_FOR_REVIEW`.

## AI made real (04-28)
Audit found `@track` and AI Review were **fakes**: `api.assistant.ask` was a
synchronous mutation answering by token-overlap against the five most recent
messages, and `api.ai.runReviewNow` keyword-filtered forty messages to create
Draft Records with no model extraction, scheduling, or failure handling.

Reworked `@track` into a model-backed Convex action with persisted stream
lifecycle, permission-safe retrieval, source evidence storage, and
running/completed/failed UI states. Reworked AI Review into model-backed
extraction with structured Draft Record creation, failure persistence, a scheduled
incremental review cron, and cursor advancement only on successful completion.

## Auth — the hard week
Multiple production auth failures, each root-caused:
- Unauthenticated `/workspace` called `auth.getCurrentUser` before redirect →
  query now skips until a Better Auth session exists.
- Convex auth context could lag Better Auth after sign-in → `ensureCurrentUser`
  returns null instead of throwing in that transient state (mobile needed a
  matching null guard).
- **Login loop root cause:** removing `ConvexBetterAuthProvider` had removed the
  cross-domain OAuth `ott` verifier, *and* the production client bundle was
  compiled against dev Convex (`enduring-impala-781`) instead of prod
  (`fleet-manatee-941`). Fixed in `c9d3433` / `22ad202`; Computer Use verified
  Google sign-in completes into the live workspace.
- Google OAuth needed two clicks because `/workspace?ott=...` rendered before the
  token was verified → routed OAuth returns through an unprotected
  `/auth/callback` and navigate only once Better Auth exposes a session.
- Stale PWA bundles kept replaying the old crash → service worker/cache refresh.

Also added email/password auth, TOTP 2FA with backup codes, profile settings,
onboarding, and a dev auth bypass (`DEV_AUTH_BYPASS=1` guard + fixed Hasan demo
identity) for local work without Google.

## Push notifications
Web/PWA had preferences but no actual notifications. Added browser permission
enablement, service-worker notification display and click routing,
preference-aware filtering (all/mentions/none), then a full Web Push pass:
PushManager subscription with the VAPID public key from Convex, stored
subscriptions, scheduled server-side delivery after message creation, and a
Node-runtime Convex action using `web-push`.

**Debug find (04-29):** three overlapping `pushManager.subscribe()` calls before
the first 45s timeout could wedge the browser push service, especially behind a
content blocker or VPN. Fixed with a single-flight guard so concurrent callers
join the active flow, plus switching the VAPID application server key from a
copied `ArrayBuffer` to a standard decoded `Uint8Array`. Shipped as `5094ea3`.

## Notable production incidents
`typingIndicators:list` errors traced twice: first, a `projects` ID sitting in the
`groups/$groupId` URL segment was promoted into `activeGroupId` before visible
groups loaded, so Convex rejected it against `v.id('groups')`; second, a
stale/invisible group ID threw `not_group_member`. Hardened by subscribing
group-scoped queries only after the active group is confirmed visible, and having
`typingIndicators:list` return an empty list for non-members.

## Performance
Agent-browser profiling found heavy dev-only overhead from always-mounted React
Grab and TanStack devtools. Added `VITE_REACT_GRAB=0` and gated devtools behind
`VITE_DEVTOOLS=1`. Disabling React Grab dropped trace events from **1,094,764 to
212,827** and long trace slices from **628 to 84**.

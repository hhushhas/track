Delivery lifecycle · where reliability comes from

Every intended alert receives a durable outcome

1 · Domain eventA message or task change commits.
2 · Delivery intentOne idempotent record per recipient membership and installation.
3 · RecheckAccess, mute, ownership, and copy are resolved at send time.
4 · Provider ticketThe transport accepts or classifies the request.
5 · ReceiptLater provider status is reconciled.
6 · TapFresh authorization opens the exact context once.
Transient failure. Retry with bounded backoff before the event expires, preserving the same idempotency key.
Permanent token failure. Disable the token, keep the installation record, and request a fresh token on a later session.

Settled delivery contract · Hasan's choices

The first-release posture is now fixed

settled

All eligible activity

New users receive joined-Channel messages, followed-thread replies, and important task events by default. Global and local mutes remain in charge.

settled

Context-aware permission

Track explains first, shows safe context with a privacy toggle, and suppresses only the banner for the exact item already visible.

settled

Direct native providers

Track sends directly to APNs and FCM with durable intents, classified acceptance, retries, security, metrics, and physical-device proof.

settled

User-controlled previews

Full mode includes a bounded message body or task title. Context and hidden modes progressively remove work content before provider submission.

settled

Measurable objective

95% accepted by APNs or FCM within 5 seconds and 99% within 30 seconds during normal provider availability.

Direct native delivery fits the product goal. APNs and FCM support interactive alerts, routing data, sounds, badges, foreground handling, and per-device provider outcomes without an Expo relay.
Honest boundary. APNs and FCM acceptance cannot prove that the operating system displayed an alert. Track owns idempotency and measurement around that boundary.

Definition of done · observable release proof

Code complete is not complete

Correctness and privacy

  • One intended alert per eligible installation; none for self-authored, muted, duplicated, or unauthorized events.
  • Sign-out, account switch, token rotation, reinstall, and invalid tokens cannot cross account boundaries.
  • Copy, badges, grouping, logs, metrics, and taps preserve exact Project membership and Acting Company access.
  • Cold, warm, and foreground taps open the exact item once or a safe unavailable state.

Verification

  • Transient failures retry, permanent failures disable the token, and every terminal outcome is visible without content-bearing logs.
  • Lint, typecheck, tests, production audit, build, and bounded code review pass.
  • One physical iPhone and one physical Android device pass foreground, background, and terminated delivery.
  • No production credential change, deployment, or rollout occurs without explicit approval.
Current status: not done. The contract is settled, but the existing prototype has not been implemented against it or passed the physical-device matrix.
